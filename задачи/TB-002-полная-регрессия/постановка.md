# Постановка: TB-002-полная-регрессия

- **Код задачи:** TB-002-полная-регрессия
- **Родитель (parentId):** TB-001-перенос-на-СТРАТУ
- **Дата постановки:** 2026-09-15

## Что нужно получить

Полная проверка функционала TBot после накатывания методологии: просмотр
всего кода (все 11 файлов, ~1500 строк) + прогон функциональных проверок
по `критерии_приёмки.md` (С1–С9 + минимальный чек-лист) с письменным
протоколом и вердиктом.

## Зачем это нужно

Правило Александра: после ЛЮБЫХ доработок — регрессионная проверка.
Перенос методологии — доработка репозитория; задача подтверждает, что бот
работает как прежде, и фиксирует протокол в памяти проекта.

## Границы работы

- Входит: чтение и анализ всего кода; офлайн-проверки (импорт, компиляция,
  kb()); живые проверки без записи в боевые таблицы, кроме контролируемой
  тестовой записи с последующим удалением (расход + задача); LLM-проверки
  (классификация, чат, edit-схема); поисковый конвейер glm_web.
- НЕ входит: правки кода (находки фиксируются как замечания, исправления —
  отдельной задачей по правилу «план → подтверждение»); деплой; проверка
  вебхука/Render (требует VPN, api.telegram.org недоступен); голосовая
  расшифровка (нет тестового аудио вне Telegram).

## Ожидаемый результат

Протокол проверки по каждому сценарию С1–С9 и пункту чек-листа:
пройдено / не применимо офлайн / замечание. Вердикт в `контекст.md`.

## Ограничения

- Не писать тестовый мусор в боевые таблицы, кроме как с немедленным
  удалением той же сессией; не дёргать Telegram API (409-конфликт с
  облачным ботом).

## Критерии приёмки

1. Каждый пункт минимального чек-листа `критерии_приёмки.md` имеет результат.
2. Каждый сценарий С1–С9 либо проверен, либо помечен «не применимо офлайн»
   с причиной.
3. По всему коду пройден обзор с фиксацией замечаний (если есть).
4. Протокол и вердикт записаны в `контекст.md` узла.
