# Архив проекта ZAKUP — поиск поставщиков (закрыт 14.09.2026, код живёт в TBot)

Проект разрабатывался в отдельной папке `D:\ZCode\Project\ZAKUP`, затем по решению Александра
был вживлён в бот «Мегастрой» (репозиторий TBot). Папка ZAKUP удалена, этот документ + zip исходников —
память о переписке и решениях. Секретов здесь нет — все ключи в `config_local.py` / `service_account.json`.

## Исходная задача (из первого сообщения Александра, 14.09.2026)

Сделать агента, помогающего искать поставщиков — и поставщиков услуг (производителей работ),
и поставщиков материалов. Сценарий:
1. Александр пишет запрос в Telegram → агент ищет по выбранным им ресурсам (ресурсы обещал описать позже).
2. В ответ в Telegram приходит выборка поставщиков со ссылками.
3. В дальнейшем: рассылка запросов на коммерческие предложения (КП) этим поставщикам, приём ответов
   на электронную почту, просмотр ответов, статус каждого запроса (пришло КП / не пришло),
   краткое содержание КП, мини-сайт (веб-страница) со всеми запросами, их статусами и ссылками на КП.

## Хронология решений

1. **Поиск (MVP)** — выбран путь «каркас с модулями-коннекторами»: ядро не знает про сайты,
   каждый источник — отдельный коннектор со стандартным ответом «название + ссылка + описание».
   Новый ресурс = новый модуль без переделки ядра.
   UX (голосовое сообщение Александра): если источник указан в тексте («найди на Авито…») —
   искать только там; если не указан — бот даёт кнопки **Авито / Яндекс Услуги / Весь интернет**
   в том же чате, где написан запрос.
2. **Хранение** — Google Sheets (как в TBot), отдельная таблица «ZAKUP: поставщики и КП».
   От облачного PostgreSQL и SQLite отказались (Render free стирает файлы; Sheets уже работает).
3. **Доступ** — Александр + Сергей (оба могут писать запросы; Александр — админ, одобряет заявки кнопкой).
4. **Почта для КП (этап 2)** — Александр зарегистрирует новую почту под задачу. Плюс он принимает КП
   в мессенджерах (Telegram, MAX) — «шину мессенджеров» заложили в архитектуру на будущее.
5. **MAX-мессенджер** — есть официальный Bot API (dev.max.ru: long polling, вебхуки, SDK);
   с августа 2025 публикация ботов переведена в «бизнес-режим» — оформить при подключении (этап 3).
6. **Способ поиска** — «поисковик сейчас + парсинг Авито позже»: сначала выдача поисковика
   с ограничением по домену; если качества не хватит — отдельным шагом глубокий парсинг Авито.
7. **Живой тест поиска выявил**: GLM Web Search API слаб на русском интернете — фильтр по домену
   avito.ru возвращает нерелевантные объявления. Решение: основной коннектор — официальный
   **Yandex Search API v2** (spec из proto yandex-cloud/cloudapi: POST /v2/web/search, ответ XML,
   оператор `site:`), GLM-поиск оставлен запасным фолбэком. Ключ Яндекса — у Александра (лимит ~500 зап/сутки).
8. **Размещение** — Александр: использовать того же бота «Мегастрой» из TBot (один бот = один приёмник
   обновлений Telegram, два процесса на одном токене конфликтуют). Выбран **вариант Б**:
   поисковый модуль вживлён в код TBot, ZAKUP-папка закрывается. Учёт в приоритете:
   «купил доски» = расход, «найди где купить доски» = поиск (классификатор `llm.extract`, action="search").

## Что сделано и проверено

- Коннекторы `searchers/`: `yandex.py` (основной), `glm_web.py` (фолбэк), стандарт `base.py::Supplier`.
- Диалог поиска: бриф (тип/что/город/объём/источник) → кнопки источника → «Ищу…» → выдача чанками ≤4000 симв.
- Голосовые запросы: распознаются glm-asr и идут в тот же конвейер.
- Таблица ZAKUP: листы Запросы / Поставщики / Пользователи созданы и проверены 14.09.2026.
- Веб-дашборд: `/` — список запросов со статусами, `/request/{№}` — поставщики; вход по паролю
  (`DASHBOARD_PASSWORD` в `config_local.py`). Живёт в том же процессе, что и бот (роут `/health` — старый health-check).
- Классификатор намерений проверен живыми вызовами GLM: 9/9 (расход/задача/задача закрыта/поиск ×4/чат/отчёт).
- Бриф-парсер: «найди на авито облицовочный кирпич 5000 шт в самаре» → материалы/кирпич/Самара/5000 шт/avito.
- Сквозной тест конвейера: выдача → фильтрация → ранжирование → список со ссылками.
- Коммит в TBot: `e6da7cb` (18 файлов: searchers/, web/, zakup_sheets.py, правки bot.py/llm.py/config).

## Грабли (технические находки переписки)

- GLM web_search: `search_domain_filter` по ру-доменам нерелевантен; `search_query` ≤70 символов.
- Yandex Search API: ответ XML (raw_data), `groupsOnPage` 1–100, `docsInGroup` 1–3, `maxPassages` 1–5.
- gspread: удаление листа — `sh.del_worksheet(ws)`, а НЕ `ws.delete()` (TBot годами тихо не удалял «Лист1»).
- Сервисный аккаунт Google имеет нулевую квоту Drive — таблицы создаёт Александр и расшаривает аккаунту
  с ролью «Редактор» (первый шаринг вышел «Читателем» — Google ответил 403, исправлено).
- PUT env-vars на Render перезаписывает ВЕСЬ набор (12 переменных — см. AGENTS.md TBot).
