# Функционал бота «Мегастрой» — паспорт для регрессионной проверки

**Правило (заверил Александр 14.09.2026):** после ЛЮБЫХ доработок кода и деплоя — пройтись по пунктам этого файла и убедиться, что главные сценарии не сломаны: компиляция, классификация GLM, кнопки, листы таблиц. Файл обновляется при каждом изменении функционала.

## 1. Доступ
- Незнакомый пользователь (текст/голос/кнопки) → функций нет; админам (ADMIN_IDS) приходит заявка с кнопками «✅ Да, открыть» / «❌ Нет».
- «Да» → строка в лист «Пользователи» (учётки переживают рестарт), пользователю «доступ открыт». «Нет» → «отказано» (до перезапуска бота).
- Пользователи = env USERS ∪ лист «Пользователи» обеих таблиц ∪ config_local.

## 2. Расходы
- «Потратил 5000 на доски для Садовой» → лист «Расходы»: Дата | День недели (авто) | Автор | Описание | Сумма | Объект | Категория.
- Категорию подбирает LLM по описанию + похожим прошлым расходам.
- Нет суммы → вопрос «На какую сумму?»; нет объекта → кнопки: последние объекты + «➕ Новый объект» → название → создатся в «Объектах».
- Новый объект создаётся ТОЛЬКО после подтверждения; если вместо названия пришёл другой диалог — ничего не создаётся.
- Известный объект подставляется молча (в т.ч. с опечатками — через LLM-сопоставление).

## 3. Задачи
- «Серёге позвонить поставщику до пятницы» → лист «Задачи»: № | Дата | День недели | Автор | Исполнитель | Задача | Срок | Статус | Объект | Закрыта.
- Нет исполнителя → вопрос «Александр или Сергей?» (синонимы Саня/Серёга нормализуются).
- «задача 5 сделана» → Статус «Сделана», дата в «Закрыта». Команды /tasks, «запросы» (/zaprosy) — списки.

## 4. Правка строк
- «Измени строку: доски для Парковой на 10000, сумма 12000» → поиск по сочетанию ВСЕХ названных признаков (объект И описание И сумма И дата).
- Одна строка → показать её целиком + «было → стало». Несколько → кнопки выбора. Ноль → «не нашёл, уточни».

## 5. Голосовые
- Голос → «🎤 Расшифровываю…» → «Распознал: … Продолжить?» кнопки «✅/❌». Да → текст идёт по обычному пути. Нет → отмена.
- Новое сообщение вместо кнопки → интерпретация отменяется.
- Модель glm-asr-2512; у aiogram Voice НЕТ file_name → getattr.

## 6. Свободное общение
- Сообщения вне учёта (action=none, нет открытого диалога) → ответ через llm.chat (кратко, по-русски, без истории). Расход/задача при этом не теряются — классификатор в приоритете.

## 7. Поиск поставщиков (ZAKUP)
- «найди бригаду по стяжке в Казани» → бриф (тип/что/город/объём/источник) → источник не указан → кнопки (Авито / Яндекс Услуги / весь интернет) → коннекторы → LLM-ранжирование → выдача чанками ≤4000 симв.
- Запись в таблицу «ZAKUP: поставщики и КП» (листы Запросы: №|Дата|Автор|Запрос|Тип|Что искать|Город|Источники|Статус|Найдено|Примечание; Поставщики: № запроса|Название|Описание|Ссылка|Источник|Статус КП|Заметки).
- Новый текст при открытом брифе → если это снова search: перезапуск брифа, иначе обычная обработка.
- **Известное ограничение**: без YANDEX_SEARCH_API_KEY работает glm_web-фолбэк — на ру-запросах даёт мусор/пусто; нормальное качество только с ключом Яндекса.

## 8. Веб
- Дашборд: вход по DASHBOARD_PASSWORD (cookie), список запросов + поставщики по ссылкам.
- /health — «TBot is alive». /notify?pass=…&text=… → ⚠️-сообщение админам в Telegram через сервер бота (ops-канал при VPN-обрывах).
- /tgwebhook и /notify и /health — вне auth-middleware дашборда.

## 9. Инфраструктурные инварианты
- Вебхук: url=https://tbot-j0kj.onrender.com/tgwebhook, секрет в заголовке; **WEBHOOK_SECRET фиксирован в env — при ротации секрета при рестарте Telegram получает 403 и теряет сообщения**; без WEBHOOK_URL — локальный polling.
- Сон бесплатного Render: холодный старт до ~60 сек; входящее сообщение будит инстанс.
- Обновление: git push → POST /v1/services/{id}/deploys → live → getWebhookInfo без ошибок.
- Env на Render — 13 переменных (см. AGENTS.md «Грабли Render API»).

## Чек-лист после доработок (минимум)
1. `python -m py_compile bot.py llm.py sheets.py zakup_sheets.py web/dashboard.py searchers/*.py`
2. llm.extract: расход / задача / поиск / none — все четыре классифицируются верно.
3. kb() вызовы без TypeError (с cols и без).
4. Листы: Расходы/Задачи читаются, Пользователи грузятся.
5. Деплой live + getWebhookInfo: url на месте, last_error пуст.
