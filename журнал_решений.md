## Решения

### Р-001. Каркас поиска с модулями-коннекторами — 2026-09-14
- **Контекст:** нужен поиск поставщиков услуг и материалов по заданным ресурсам.
- **Решение:** ядро не знает про сайты; каждый источник — отдельный коннектор
  со стандартным ответом «название + ссылка + описание»
  (`searchers/base.py::Supplier`). Новый ресурс = новый модуль + строка в SOURCES.
- **Последствия:** расширение без переделки ядра; стандарт описан в паспорте.

### Р-002. Хранение ZAKUP в Google Sheets — 2026-09-14
- **Контекст:** куда писать запросы и поставщиков.
- **Решение:** отдельная таблица «ZAKUP: поставщики и КП» (как учётная — Sheets).
- **Альтернативы:** облачный PostgreSQL, SQLite — отвергнуты: Render free
  стирает файлы; Sheets уже работает.
- **Последствия:** листы Запросы/Поставщики/Пользователи созданы и проверены 14.09.2026.

### Р-003. Основной коннектор — Yandex Search API v2 — 2026-09-14
- **Контекст:** живой тест показал: GLM Web Search API слаб на русском
  интернете — фильтр по домену avito.ru возвращает нерелевантные объявления.
- **Решение:** основной коннектор `yandex.py` — официальный Yandex Search API v2
  (spec из proto yandex-cloud/cloudapi: POST /v2/web/search, ответ XML,
  оператор `site:`); GLM-поиск — запасной
  фолбэк `glm_web.py`. Ключ Яндекса у Александра (лимит ~500 зап/сутки).
- **Последствия:** пока ключа нет, поиск работает через фолбэк с плохим
  качеством (см. критерии С7, известное ограничение).

### Р-004. ZAKUP вживлён в TBot, отдельная папка закрыта — 2026-09-14
- **Контекст:** два процесса на одном токене конфликтуют; один бот = один
  приёмник обновлений Telegram.
- **Решение:** вариант Б — поисковый модуль вживлён в код TBot
  (коммит `e6da7cb`: 18 файлов — searchers/, web/, zakup_sheets.py,
  правки bot.py/llm.py/config); папка ZAKUP удалена.
- **Последствия:** учёт в приоритете классификации: «купил доски» = расход,
  «найди где купить доски» = поиск (`llm.extract`, action="search").

### Р-005. Webhook вместо keep-alive — 2026-09 (коммит 62a944c)
- **Контекст:** keep-alive через GitHub Actions ненадёжен (cron */10
  растягивается до ~2 ч), бесплатный Render засыпает.
- **Решение:** Telegram webhook (`WEBHOOK_URL`, путь `/tgwebhook`); входящее
  сообщение будит инстанс. Локально (без WEBHOOK_URL) — long polling.
- **Последствия:** WEBHOOK_SECRET стабилен, не ротировать (см. паспорт);
  Actions остаётся «как бонус».

### Р-006. Доступ по заявкам через кнопки — 2026-09 (коммит 3f26776)
- **Контекст:** бот для партнёров, но токен публично известен.
- **Решение:** незнакомый пользователь делает заявку; админ одобряет кнопками;
  одобренные хранятся в листе «Пользователи» (переживают рестарт).
- **Последствия:** белый список = env USERS ∪ листы обеих таблиц ∪ config_local.

### Р-007. Голосовые через GLM ASR с подтверждением — 2026-09 (коммит ab26e94)
- **Решение:** glm-asr-2512, расшифровка → кнопки «Да/Нет» → обычный конвейер.
- **Последствия:** грабля: у aiogram `Voice` нет `file_name` → getattr (инвариант).

### Р-008. Ops-эндпоинт /notify — 2026-09 (коммит ab203e7)
- **Контекст:** при VPN-обрыве на ПК агент не может сообщить Александру в чат.
- **Решение:** `GET /notify?pass=…&text=…` → ⚠️-сообщение админам через сервер
  бота (облако достаёт Telegram всегда).

### Р-009. Свободный чат без истории — 2026-09 (коммит 82fd8f2)
- **Решение:** сообщения вне учёта (action=none) → `llm.chat`, кратко, без
  истории; классификатор в приоритете — расход/задача не теряются.

## Архив ZAKUP (влит из docs/zakup_history.md, закрыт 14.09.2026)

Проект разрабатывался в `D:\ZCode\Project\ZAKUP`, затем вживлён в бот
«Мегастрой» (см. Р-004). Папка ZAKUP удалена; память — этот раздел и
`docs/zakup_archive_2026-09-14.zip` (исходники без секретов и .venv,
с git-историей в 1 коммит и согласованным планом
`.zcode/plans/plan-sess_938172a8….md`).

**Исходная задача (Александр, 14.09.2026):** агент для поиска поставщиков
(услуги и материалы): запрос в Telegram → выборка поставщиков со ссылками;
в дальнейшем — рассылка запросов на КП, приём ответов по почте, статусы КП
(пришло / не пришло), краткое содержание КП, мини-сайт со всеми запросами,
их статусами и ссылками на КП.

**Что сделано и проверено:** коннекторы `searchers/`; диалог поиска (бриф →
кнопки источника → «Ищу…» → выдача чанками ≤4000 симв.); голосовые запросы
через glm-asr в тот же конвейер; таблица ZAKUP (листы созданы и проверены
14.09.2026); веб-дашборд (`/` — запросы, `/request/{№}` — поставщики, вход по
паролю из `config_local.py`, процесс общий с ботом); классификатор намерений
проверен живыми вызовами GLM 9/9 (расход/задача/задача закрыта/поиск ×4/чат/
отчёт); бриф-парсер («найди на авито облицовочный
кирпич 5000 шт в самаре» → материалы/кирпич/Самара/5000 шт/avito); сквозной
тест конвейера (выдача → фильтрация → ранжирование → список со ссылками).

**Грабли (находки):**
- GLM web_search: `search_domain_filter` по ру-доменам нерелевантен;
  `search_query` ≤70 символов.
- Yandex Search API: ответ XML (raw_data), `groupsOnPage` 1–100,
  `docsInGroup` 1–3, `maxPassages` 1–5.
- gspread: удаление листа — `sh.del_worksheet(ws)`, а НЕ `ws.delete()`
  (TBot годами тихо не удалял «Лист1»).
- Сервисный аккаунт Google имеет нулевую квоту Drive — таблицы создаёт
  Александр и расшаривает аккаунту с ролью «Редактор» (первый шаринг вышел
  «Читателем» — Google ответил 403, исправлено).
- PUT env-vars на Render перезаписывает ВЕСЬ набор (13 переменных —
  `артефакты/tbot.json` → delivery).
